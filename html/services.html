Programming Foundations

The starting point most people skip.

Foundations is where you learn to think in programs — how to break a problem into steps, name things well, and use the tools every developer touches daily.

  • Decomposing problems before writing a line of code.
  • Working comfortably in the terminal from day one.
  • Committing, branching, and reading your own history.
  • Functions, data shapes, and when to split logic apart.

Frontend Development Track

Interfaces that hold up under real use.

The frontend track is where your work becomes visible and the feedback becomes immediate. You build layouts that survive every screen size, write markup assistive technology understands, and keep JavaScript predictable.

  • Layout systems, spacing rhythm, and typographic hierarchy.
  • Keyboard paths, focus states, and contrast as default habits.
  • Mobile-first thinking rather than shrinking desktop layouts.
  • Performance basics: asset sizing, layout stability, lean JS.

See the frontend syllabus

Backend Development Track

The rules, the data, and the contracts between them.

Backend work is quiet and structural. You design routes around resources, model data that won’t fight you later, and write tests that catch problems before they reach a user.

  • Endpoint design centred on resources, not screens.
  • Schema thinking: relationships, constraints, migrations.
  • Validation, error handling, and safe auth fundamentals.
  • Unit and integration tests written beside the feature.

Full-Stack Development Track

One product, every layer, your name on it.

The full-stack track is where separate skills become a single system. You design the interface, build the API, shape the database, deploy the result, and then explain your decisions out loud.

  • Draw the architecture before writing the first component.
  • Connect client and server with clear contracts between them.
  • Ship it, document it, and defend it in a project review.

Project Labs

Where the syllabus turns into something that runs.

Project Labs are open-ended builds with real acceptance criteria. You choose the approach, the review is deeper, and the deliverable is something you could show a hiring team.

Sample lab brief labs/booking-flow.md

Availability-aware booking flow

Build a two-step booking form backed by an availability endpoint. Validation must happen client-side before submit and again on the server. The completed flow should work with a keyboard alone.

  • Two-step form with clear field-level errors
  • Availability endpoint returns conflict states
  • Full keyboard path verified end to end
  • Review-ready pull request with context

Plan the architecture

Sketch the components, routes, and data shape before coding.

Build in small, reviewable steps

Small commits, focused branches, and a PR that tells a story.

Submit for peer & mentor review

Two rounds of feedback — one from a peer, one from a mentor.

Iterate and merge

Respond to comments, push follow-ups, and merge when approved.

Code Review & Mentorship

Feedback tied to the code you actually wrote.

Every program includes structured review. Mentors read your work, ask why you made specific choices, and offer alternatives with honest tradeoffs — not just corrections.

  • Line-level comments with reasoning, not just flags.
  • Live pairing sessions when a concept refuses to click.
  • Strengths named as clearly as weaknesses.
  • Threads stay attached to the code so you can revisit later.

Career-Readiness Workshops

Prepare for the conversation, not just the code test.

Stackly does not promise job placement. What we do offer is structured practice in the skills hiring teams actually evaluate: explaining your work, reading a brief carefully, and knowing your own code well enough to defend it.

Portfolio & Capstone Support

Your capstone becomes the proof.

The capstone is the final program milestone: a complete product with a written case study, deployed and documented. Mentors work with you on scope, structure, and storytelling so the finished piece genuinely represents what you can do.

  • Scope-cutting sessions so the project actually finishes.
  • Architecture review before and during the build.
  • Case study writing: problem, decisions, tradeoffs, next steps.
  • Presentation practice with mentor feedback before the final demo.

Inventory Tracker

Full-stack · Node · SQL · Vanilla JS

Problem

Small shops track stock in spreadsheets that break whenever two people edit at once.

Key decisions

Learning Support & Program Format

How the programs are actually structured.

Stackly programs are cohort-based, project-first, and paced so you can hold a job or study alongside. The details below describe the format rather than specific schedules.

Cohort-based

You move through the program alongside a peer group that stays with you from start to capstone.

Flexible pacing

Modules can be revisited. Where a concept needs more time, that time exists.

Review at every stage

Peer review before mentor review. Both rounds sharpen the work and the learner.

Accessibility built in

Support for different learning styles, formats, and accessibility needs.

Open support channels

Real people to talk to when something isn’t clicking — not just a FAQ page.

Revised each run

Curriculum is adjusted based on learner feedback, not locked in place.

Specific track timelines and cohort dates are coordinated directly with the Stackly team.
